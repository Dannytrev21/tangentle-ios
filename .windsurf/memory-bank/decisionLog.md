# Decision Log

> **Update Trigger**: After any significant architectural, design, or implementation decision. This file is **append-only** - never remove entries.

## How to Add Entries

Add new decisions at the top of the Decisions section using this format:

```markdown
### {YYYY-MM-DD} - {Decision Title}
**Context**: {Why this decision was needed}
**Options Considered**:
1. {Option 1}: {pros/cons}
2. {Option 2}: {pros/cons}
**Decision**: {What was decided}
**Rationale**: {Why this option was chosen}
**Consequences**: {Expected impact, trade-offs}
**Status**: {Active/Superseded by {reference}}
```

## Decision Categories

For reference, decisions typically fall into these categories:

- **Architecture**: System structure, component boundaries
- **Technology**: Framework, library, tool choices
- **Design**: API design, data modeling
- **Process**: Development workflow, testing strategy
- **Trade-off**: Performance vs. maintainability, etc.
